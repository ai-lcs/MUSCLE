# 论文方法与代码怎样对应

这份文档用于把论文中的概念定位到公开代码。它不是逐行代码注释。

## 总体对应表

| 论文内容 | 主要代码位置 | 阅读时关注什么 |
|---|---|---|
| 训练、验证与测试流程 | `main.py` | 参数、DataLoader、训练循环、checkpoint 和指标 |
| 数据读取与增强 | `datasets/` | 数据路径、类别数、划分方式和图像变换 |

## 多尺度特征来自哪里

论文把骨干网络不同阶段的输出作为不同尺度特征。

ResNet 版本默认关注：

```text
layer1
layer2
layer3
layer4
```

这些层的空间尺寸和通道数不同。浅层通常保留更多纹理和空间细节，深层通常包含更强的语义信息。

`need_layer_name_list` 控制需要使用哪些层。

## MAFC 在代码中的表现

论文中的 Multi-Axis Feature Compression 会沿 C、H、W 三个方向处理特征。

在代码中可以看到特征维度交换、`SpatialAttention` 和 `FeatureSqueeze`。三个方向的输出被拼接后，送入证据网络。

阅读大量 `permute()` 时，不必把它理解成新的深度学习算法。它主要在交换张量轴，让同一套压缩逻辑能够分别处理通道、高度和宽度。

## 证据怎样产生

`EvidenceCollector` 接收压缩后的特征，并输出每个类别的 evidence。

公开实现使用 Softplus，使 evidence 非负。随后损失函数使用：

```text
alpha = evidence + 1
```

`alpha` 是 Dirichlet 分布参数。证据总量越少，模型得到的整体不确定性越高。

这里的 evidence 是模型内部的类别支持量，不是医学临床证据。

## 多尺度证据怎样聚合

`TMSL.forward()` 先收集每个尺度的 evidence，然后执行逐步平均：

```python
evidence_a = evidences[0]
for i in range(1, len(evidences)):
    evidence_a = (evidences[i] + evidence_a) / 2
```

论文的二元意见聚合中，Dirichlet 参数同样采用两两平均。需要注意，连续两两平均三个以上尺度时可能与聚合顺序有关。

例如先合并尺度 1 和尺度 2，再与尺度 3 平均，尺度 3 的数值权重会更大。后续复现可以尝试改变尺度顺序，观察指标和不确定性是否变化。

## 两阶段训练怎样体现在代码中

普通模型名称：

```text
ResNet
VanillaNet
SwinTransformer
```

第二阶段模型名称：

```text
ResNet_CHW_SAFS_TMSL
VanillaNet_CHW_SAFS_TMSL
SwinTransformer_CHW_SAFS_TMSL
```

第二阶段模型通过 `ckpt_path` 加载第一阶段模型参数，并把 `original_net` 冻结。

因此，正确的最小流程不是直接运行 MUSCLE，而是：

```text
训练普通骨干
→ 保存最佳 checkpoint
→ 创建对应 MUSCLE 模型
→ 加载 checkpoint
→ 验证骨干参数已冻结
→ 训练 MAFC 和证据支路
```

## 当前值得继续核查的地方

- 逐步证据平均是否明显受尺度顺序影响；
- 第一阶段 checkpoint 加载时，分类头尺寸不同会怎样处理；
- 论文中“意见聚合”与代码中的 evidence 平均是否完全等价；
- 固定随机种子后能否稳定得到相似结果；
- 不同尺度的不确定性是否真的与特征质量一致；
- 在真实分布外数据上，不确定性是否仍然可靠。
