# 哪些文件应保留，哪些不能上传

这个仓库是公开的。整理文件时不能只看“是否有用”，还要考虑体积、版权、隐私、许可证和能否复现。

## 适合放进 GitHub

| 内容 | 是否上传 | 原因 |
|---|---|---|
| 原作者公开的 Python 源码 | 保留 | 是 fork 的主体，受 MIT License 约束 |
| `LICENSE` | 必须保留 | MIT 要求保留版权和许可文本 |
| 中文 README 和学习文档 | 可以上传 | 便于理解项目和记录进度 |
| 小型配置文件 | 可以上传 | 有助于复现实验设置 |
| 运行命令和参数说明 | 可以上传 | 便于以后重复实验 |
| 小体积汇总指标 | 可以上传 | 例如手工整理的 Markdown 表格 |
| 修复后的通用代码 | 可以上传 | 应说明改动原因，并避免只适配个人绝对路径 |

## 只应留在本机

| 内容 | 为什么不能上传 |
|---|---|
| `.venv-cpu` 或其他虚拟环境 | 文件数量大、平台相关，不能代替依赖清单 |
| 医学图像数据集 | 体积大，且可能受数据集协议、隐私和再分发限制 |
| `*.pth`、`*.pt`、`*.ckpt` 权重 | 体积大；来源和授权需要单独确认 |
| 论文 PDF | 论文受出版商版权保护，不应直接放进公开仓库 |
| 含 IEEE 原图的个人导读 PDF | 适合本地学习，不适合未经许可公开再分发 |
| TensorBoard 日志和逐样本预测 | 体积可能快速增长，也可能包含数据路径等本机信息 |
| API Key、Token、密码 | 属于敏感信息，绝不能提交 |
| 本机绝对路径配置 | 暴露目录结构，也不能在他人电脑上复用 |
| 临时 CSV 划分文件 | 未固定生成逻辑时容易造成口径混乱 |

## 为什么不删除原始代码

当前 fork 与上游原始提交一致，没有发现需要为了“看起来简洁”而删除的源码。

即使暂时只准备使用 ResNet，也不应删除 VanillaNet、Swin Transformer 或五套数据读取代码。它们属于论文完整实现，也为后续理解不同骨干下的 MUSCLE 提供依据。

整理阶段只增加文档和忽略规则，不改动算法。

## 为什么 LICENSE 不翻译

`LICENSE` 是具有法律意义的 MIT 许可文本。中文说明可以解释其作用，但不应使用非官方翻译替换原文。

需要保留：

```text
MIT License
Copyright (c) 2026 Q4CS
```

使用或修改代码时，也应保留原作者的版权和许可说明。

## `.gitignore` 能做什么

仓库根目录新增的 `.gitignore` 会排除：

- Python 缓存和虚拟环境；
- 数据与下载目录；
- 医学图像常见格式；
- 模型权重和 checkpoint；
- 训练输出、日志和 TensorBoard 文件；
- 论文 PDF 和压缩包；
- 本地配置及临时文件。

`.gitignore` 只能防止尚未被 Git 跟踪的文件进入提交。如果某个大文件已经提交过，后来再加入忽略规则并不会自动删除历史记录。

## 每次提交前的自检

提交前至少确认：

1. 没有数据、权重、PDF 和虚拟环境；
2. 没有 Token、密码和 `.env`；
3. 没有写死个人电脑绝对路径；
4. 文档中的链接可以打开；
5. 结果描述没有把 smoke test 写成论文复现；
6. 原作者和论文引用仍然清楚；
7. 只提交本次任务相关文件。
