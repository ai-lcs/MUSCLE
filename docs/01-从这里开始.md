# 从这里开始：先建立项目地图

如果你刚开始学 Python，直接打开 MUSCLE 的几千行代码，很容易同时遇到四种问题：

- 不认识 Python 语法；
- 不理解 PyTorch 的张量、模型和训练循环；
- 不知道医学图像数据怎样读取；
- 不理解论文中的多尺度和证据理论。

这些问题混在一起时，会产生“每一行都看不懂”的感觉。更合适的办法不是硬啃，而是先建立项目地图。

## 先知道输入和输出

MUSCLE 做的是医学图像分类。

输入是一批医学图像，程序将它们整理成形状近似于：

```text
批次大小 × 通道数 × 图像高度 × 图像宽度
```

对于普通 RGB 图像，通道数通常为 3。模型的最终输出是每张图像对应各个类别的判断。

它不是病灶分割模型，不会直接画出病灶边界；也不是目标检测模型，不会输出病灶方框。

## 再看两阶段训练

MUSCLE 不是从零开始一次性训练完成。

第一阶段训练普通骨干网络，例如 ResNet。这个阶段的目标是让骨干网络先学会基本分类，并保存表现最好的 checkpoint。

第二阶段创建带 MUSCLE 的模型，加载第一阶段 checkpoint，并冻结骨干网络。新的多尺度压缩和证据融合模块继续训练。

```text
第一阶段：图像 → 骨干网络 → 普通分类结果

第二阶段：图像 → 已训练且冻结的骨干网络
                 ↓
             多阶段特征
                 ↓
          MAFC + 证据网络
                 ↓
             聚合分类结果
```

如果没有第一阶段 checkpoint，第二阶段就缺少经过训练的骨干特征。这是复现时非常关键、也容易忽视的条件。

## 当前最需要认识的术语

| 术语 | 在这个项目里的意思 |
|---|---|
| backbone | 骨干网络，负责从图像中提取特征，例如 ResNet |
| feature map | 特征图，网络处理图像后形成的中间表示 |
| multi-scale | 使用骨干网络不同深度阶段的特征 |
| MAFC | 从通道、高度和宽度三个方向压缩特征 |
| evidence | 模型对不同类别给出的非负支持量 |
| uncertainty | 根据证据总量计算的整体不确定性 |
| checkpoint | 保存下来的模型参数文件，常见扩展名为 `.pth` |
| epoch | 模型完整看过一遍训练集 |
| batch size | 一次送入模型的样本数量 |
| DataLoader | PyTorch 中负责按批次提供数据的工具 |

## 推荐的代码阅读顺序

先看 [代码结构导读](02-代码结构导读.md)，了解每个文件的职责。

随后只追踪一条调用链：

```text
main.py
→ set_loader()
→ set_model()
→ net_factory()
→ model(image_batch)
→ loss
→ backward()
→ optimizer.step()
```

暂时不要研究每种数据增强、每个网络 block 和每条数学公式。等调用链能说清后，再根据 [论文方法与代码对应](03-论文方法与代码对应.md) 定位具体实现。

## 当前不要做的事

- 不要直接下载五套完整数据；
- 不要直接运行默认 200 个 epoch；
- 不要把数据路径随便改成一个并不存在的目录；
- 不要把第一次成功导入模型称为论文复现；
- 不要让 AI 一次性重写整个仓库；
- 不要上传数据集、模型权重、论文 PDF 或虚拟环境。

这一步的合格标准不是“看懂全部代码”，而是能说明：程序从哪里读取数据、在哪里创建模型、怎样训练、怎样保存结果，以及 MUSCLE 比普通骨干多出了哪些模块。
